

## Что делает этот промпт

Этот промпт просит ИИ собрать страницы входа и регистрации для Landed. Обе используют magic link (вход по ссылке из письма). Это значит, что пароля нет. Пользователь вводит свою почту, мы отправляем ему ссылку, и по клику на ссылку он входит.

Landed уже работает именно так. Форма живёт в `components/organisms/auth/magic-link-form.tsx`, а ссылка возвращается в `app/auth/callback/route.ts`.

Собери страницы аутентификации на magic link от Supabase. Никаких паролей, никакого входа через соцсети. Только email.

Нам нужны две страницы: вход (sign in) и регистрация (sign up). Обе работают одинаково — одно поле для email и одна кнопка, которая отправляет magic link.

## Страница входа по адресу /sign-in

Центрированная карточка, максимальная ширина 400px, на нашем тёмном холсте (#0d0d0d).

Внутри:
- Короткий заголовок: "Sign in to Landed"
- Одно поле email с лейблом "Email" и подсказкой "We'll send a sign-in link — no password needed"
- Одна salmon-кнопка на всю ширину: "Send magic link"
- Под формой: "New here?" со ссылкой на /sign-up

Когда пользователь отправляет форму:
1. Вызови Supabase auth signInWithOtp с его email.
2. Установи email redirect на /auth/callback.
3. Замени форму на состояние "check your email": заголовок "Check your email" и текст "We sent a sign-in link to your email. Open it on this device to continue."
4. Если Supabase вернул ошибку, покажи короткое сообщение под формой.

## Страница регистрации по адресу /sign-up

Тот же макет и то же поведение, что и на входе. Меняются только слова:
- Заголовок: "Create your Landed account"
- Кнопка: "Send magic link"
- Под формой: "Already have an account?" со ссылкой на /sign-in
- После отправки покажи то же состояние "check your email".

Supabase создаёт аккаунт при первом входе, поэтому регистрация и вход разделяют один поток.

## Маршрут auth callback

Создай маршрут по адресу /auth/callback.
- Прочитай "code" из URL.
- Обменяй его на сессию через Supabase (exchangeCodeForSession).
- При успехе сделай редирект на / (приложение).
- При неудаче сделай редирект на /sign-in?error=auth.

## Защити приложение

Основное приложение живёт в группе маршрутов (app)/ за оболочкой (shell).
- Если пользователь не вошёл, сделай ему редирект на /sign-in.
- Делай эту проверку в layout оболочки (или в middleware), используя серверный клиент Supabase и getUser.
- Вошедших пользователей, которые открывают /sign-in, отправляй на / вместо этого.

## Дизайн

- Используй дизайн-систему для всего оформления. Тёмная тема.

- Текст ошибки маленький и приглушённо-красный. Дружелюбный к мобильным, с отступами по бокам.

## Как этим пользоваться

1. Убедись, что Supabase настроен и твои ключи лежат в `.env.local` (`NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY`).
2. Вставь промпт в свой ИИ-инструмент.
3. Перейди на `http://localhost:3009/sign-up` и введи свою почту.
4. Проверь входящие: там должен быть magic link. Кликни по нему. Ты должен вернуться в приложение уже вошедшим.
5. Выйди, затем попробуй открыть приложение напрямую. Оно должно перекинуть тебя на `/sign-in`.

## Советы

- В дашборде Supabase добавь `http://localhost:3009/auth/callback` в список разрешённых redirect URL, иначе ссылка не сработает.
- Если письмо не приходит, проверь спам. Встроенная почта Supabase годится для тестов, но медленная.
- Magic link открывается на том же устройстве, с которого начали поток. Скажи об этом пользователю в тексте "check your email".
- Нет паролей — значит, нечего утекать. В этом здесь выигрыш по безопасности.
