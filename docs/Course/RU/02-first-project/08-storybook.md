## Что такое Storybook

Storybook — это изолированная мастерская для твоих компонентов. Она позволяет открыть один компонент за раз и посмотреть на него отдельно, во всех его состояниях, не запуская всё приложение.

Представь так. Обычно, чтобы увидеть кнопку, тебе нужно запустить JobTracker, войти, открыть страницу и найти, где кнопка появляется. Со Storybook ты просто открываешь Button и смотришь на него: состояние по умолчанию, отключённое, состояние загрузки, состояние при наведении — всё рядом.

## Почему это подходит для вайбкодинга

JobTracker построен на **атомарном дизайне**. Ты сначала собираешь маленькие кусочки, а потом соединяешь их:

- **атомы** — самые маленькие кусочки (button, input, badge, spinner)
- **молекулы** — несколько атомов вместе (chat-composer, form-field, status-badge)
- **организмы** — блоки покрупнее (kanban-board, chat-panel, application-form)

Storybook идеально подходит для такого способа работы:

- **Собирай снизу вверх.** Сделай атом, проверь его в Storybook, потом используй внутри молекулы.
- **Проверяй каждый кусочек изолированно.** Если бейдж выглядит неправильно, ты чинишь его в мастерской, а не копаясь во всём приложении.
- **Покажи ИИ, как выглядит «правильно».** Когда компонент работает в Storybook, у тебя есть чёткий, изолированный пример. Гораздо проще сказать ИИ «Button должен выглядеть вот так», когда Button стоит отдельно.

Ещё это ловит проблемы заранее. Аддон a11y (`@storybook/addon-a11y`) помечает проблемы доступности, например плохой контраст цветов, прямо в мастерской.

## Как запустить

Запусти мастерскую:

```bash
npm run storybook
```

Это откроет Storybook по адресу **http://localhost:6006**. Ты увидишь боковую панель со всеми компонентами. Кликни на один, чтобы посмотреть. Меняй его пропсы (их называют «controls»), чтобы вживую видеть разные состояния.

Собери статичную версию (папку с обычным HTML, которую можно захостить или поделиться):

```bash
npm run build-storybook
```

Это запишет результат в папку `storybook-static/`.

## Вариант полегче: /design

В JobTracker также есть более простая витрина внутри приложения. Запусти приложение и зайди на **/design**. Она отрисовывает дизайн-систему на одной странице (код в `components/design-system/showcase.tsx`).

Что использовать?

- Используй **/design** для быстрого взгляда на токены и компоненты внутри реального приложения, с реальными стилями.
- Используй **Storybook**, когда хочешь поковырять состояния одного компонента, пощёлкать controls и проверить доступность изолированно.

## Про storybook-static/

`storybook-static/` — это **сгенерированная** папка. Это результат сборки, а не исходный код, который ты писал. Поэтому:

- Она должна быть в `.gitignore` (не коммить её).
- Её нужно исключить из линтинга (не линти сгенерированные файлы).

Если ты видишь ошибки линтера или огромный diff из `storybook-static/`, это признак того, что папка проскользнула мимо `.gitignore`. Верни её обратно и убери из Git.

## Советы

- Держи Storybook запущенным во второй вкладке терминала, пока собираешь компонент. Сохрани файл — и мастерская обновится мгновенно.
- Добавляй story для каждого нового атома и молекулы. Это самый быстрый способ проверить каждое состояние, не кликая по всему приложению.
- Используй аддон a11y, чтобы поймать проблемы с контрастом и подписями до того, как они попадут на страницу.
- Никогда не коммить `storybook-static/`. Это сгенерированная папка — пересобери её в любой момент через `npm run build-storybook`.
