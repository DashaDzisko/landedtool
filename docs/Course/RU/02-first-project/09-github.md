## Что такое GitHub

GitHub — это место, где твой код живёт онлайн. Думай о нём как об облачном хранилище для кода. Как Google Drive, но для проектов.

Он делает две важные вещи:

1. **Резервная копия.** Если твой компьютер сломается, код в безопасности на GitHub.
2. **История версий.** Ты можешь вернуться к любой предыдущей версии проекта. Если что-то сломал — можешь откатить.

GitHub также нужен, чтобы задеплоить приложение на Vercel. Vercel читает твой код с GitHub.

## Что такое Git

Git — это инструмент, который отслеживает изменения в твоём коде. GitHub — это сайт, где ты хранишь эти изменения.

Тебе не нужно глубоко изучать Git. Нужно несколько базовых команд. Или можешь попросить ИИ выполнить их за тебя.

Хорошая новость: JobTracker **уже является Git-репозиторием**. Папка `.git` на месте, и коммиты уже есть. Так что тебе не нужно запускать `git init`. Ты просто продолжаешь коммитить поверх того, что есть.

## Залей его на GitHub (если его там ещё нет)

Если проект живёт только на твоём компьютере, залей его на GitHub один раз:

### Шаг 1: Создай аккаунт на GitHub

Зайди на github.com и зарегистрируйся. Это бесплатно.

### Шаг 2: Создай репозиторий

Репозиторий (или «репо») — это дом твоего проекта на GitHub. Нажми кнопку «+» и выбери «New repository». Дай ему имя. Оставь публичным или приватным — на твой выбор.

Или попроси ИИ:

«Создай новый GitHub-репозиторий с именем jobtracker и залей туда мой проект.»

### Шаг 3: Подключи и залей

Попроси ИИ:

«Подключи этот проект к моему GitHub-репозиторию на github.com/your-username/jobtracker и залей его.»

ИИ выполнит нужные Git-команды за тебя.

## Базовый рабочий процесс с Git

Каждый раз, когда ты доделываешь фичу или что-то чинишь, сохраняй изменения на GitHub. Есть два способа это сделать.

### Вариант A: Попроси ИИ

Просто скажи:

«Закоммить мои изменения и запушь на GitHub.»

Или чуть конкретнее:

«Закоммить мои изменения с сообщением 'add kanban drag and drop' и запушь на GitHub.»

### Вариант B: Сделай сам

Три команды в терминале:

```bash
git add .
git commit -m "add kanban drag and drop"
git push
```

- `git add .` говорит Git, какие файлы изменились
- `git commit -m "message"` сохраняет изменения с коротким описанием
- `git push` отправляет их на GitHub

### Как часто коммитить

Коммить после каждой фичи, которая работает. Не после каждого мелкого изменения. Не раз в неделю.

Хорошие моменты для коммита:
- Ты доделал новую страницу или компонент
- Ты починил баг
- Ты добавил новый инструмент агента, который работает
- Ты применил миграцию базы данных

## Файл .gitignore

Некоторые файлы не должны попадать на GitHub. Например, твои API-ключи. Файл `.gitignore` говорит Git, какие файлы пропускать.

В JobTracker `.gitignore` уже пропускает:

- `.env.local` — где живут твои ключи Supabase и OpenAI
- `node_modules` — большая папка с пакетами
- `storybook-static/` — сгенерированный результат Storybook
- `.next` — результат сборки

Не убирай ничего из `.gitignore`, если не знаешь точно, что делаешь. В частности, никогда не убирай `.env.local`. Если твои ключи попадут на GitHub, любой сможет ими воспользоваться.

## Частые проблемы

**«Permission denied»:** Тебе нужно настроить аутентификацию. Попроси ИИ: «Помоги мне настроить аутентификацию GitHub на моём компьютере.»

**«Your branch is behind»:** Кто-то (или ты с другого компьютера) изменил код на GitHub. Сначала запусти `git pull`, потом попробуй снова.

**Ты закоммитил то, что не должен был:** Если ты случайно запушил свой `.env.local` с настоящими ключами, немедленно смени их. Создай новый ключ Supabase anon и новый ключ OpenAI. Старые ключи остаются в истории GitHub даже после того, как ты удалишь файл.

## Советы

- Пиши короткие сообщения коммитов, которые говорят, что ты сделал. «add status badge colors» лучше, чем «update».
- Не коммить сломанный код. Если что-то сломано, сначала почини или откати изменение.
- Запускай `git status` перед коммитом. Он показывает ровно то, что будет сохранено.
- Иногда заглядывай на сайт GitHub. Это хороший способ увидеть проект со стороны.
