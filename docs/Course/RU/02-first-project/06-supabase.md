## Что такое Supabase

Supabase — это сервис, который даёт тебе две вещи:

1. **База данных** — место для хранения твоих данных (заявки, чаты, заметки, контакты)
2. **Аутентификация** — способ для людей регистрироваться и входить в твоё приложение

Тебе не нужно строить это самому. Supabase делает это за тебя. Ты просто подключаешь его к своему приложению. В JobTracker Supabase хранит каждую заявку на работу, каждый чат с ИИ и профиль каждого пользователя.

## Почему Supabase

- У него есть бесплатный план, которого достаточно для твоего первого проекта.
- Он хорошо работает с Next.js. JobTracker использует `@supabase/supabase-js` и `@supabase/ssr`.
- ИИ очень хорошо знает Supabase. Он может написать код подключения за тебя.
- Ты можешь видеть свои данные в визуальной таблице, как в электронной таблице. Это удобно, если ты не привык к базам данных.

## Как его настроить

### Шаг 1: Создай аккаунт

Зайди на supabase.com и зарегистрируйся. Это бесплатно.

### Шаг 2: Создай новый проект

Нажми "New project". Дай ему имя. Выбери пароль для базы данных (сохрани его где-нибудь в надёжном месте). Выбери регион поближе к твоим пользователям.

Подожди минуту, пока он настроится.

### Шаг 3: Получи свои ключи

Зайди в Project Settings > API. Тебе нужны две вещи:

- **Project URL** — адрес твоей базы данных
- **Anon key** — публичный ключ для твоего приложения

### Шаг 4: Добавь ключи в свой проект

Скопируй `.env.example` в `.env.local` в корне проекта. Впиши свои ключи:

```
NEXT_PUBLIC_SUPABASE_URL=https://<your-ref>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon-key>
```

Файл `.env.local` работает на твоём компьютере. Когда ты деплоишь на Vercel, тебе нужно будет добавить эти ключи и там тоже. Как это сделать — смотри в руководстве по Vercel.

Anon key безопасен для браузера. Твои данные защищены не тем, что ключ спрятан. Они защищены Row Level Security (об этом ниже).

## Что такое база данных

Если ты никогда не пользовался базой данных, представь её как набор электронных таблиц. Каждая таблица называется table. Каждая строка — один элемент. Каждый столбец — свойство этого элемента.

В JobTracker есть такие таблицы:

- `profiles` — одна строка на пользователя (имя, краткое содержание CV, целевые роли)
- `applications` — заявки на работу (компания, роль, статус, зарплата...)
- `status_entries` — таймлайн изменений статуса для каждой заявки
- `notes` — заметки, прикреплённые к заявке
- `contacts` — контактное лицо для заявки
- `chats` — каждая ветка чата с ИИ
- `chat_messages` — сообщения внутри чата

Пример: несколько строк из таблицы `applications`

| id | company | role | status | applied_at |
|----|---------|------|--------|------------|
| a1 | Figma | Product Designer | applied | 2026-07-01 |
| a2 | Linear | Design Engineer | interview | 2026-07-10 |

Всё это можно посмотреть в дашборде Supabase. Он выглядит как редактор электронных таблиц.

## Что такое SQL

SQL — это язык, которым ты общаешься со своей базой данных. Он говорит базе, что делать: получить данные, добавить данные, обновить данные, удалить данные.

Тебе не нужно учить SQL. Но полезно знать, как он выглядит.

**Получить данные:**
```sql
select * from applications;
```
Это значит: дай мне все строки из таблицы `applications`.

**Добавить данные:**
```sql
insert into applications (company, role) values ('Figma', 'Product Designer');
```

Ты редко будешь писать SQL руками. В JobTracker приложение читает и записывает данные за тебя через хелперы в `lib/db/`.

## Миграции: как создаются таблицы

Таблицы JobTracker не собираются кликами вручную. Они описаны в SQL-файлах, которые называются **миграциями**, в `supabase/migrations/`:

- `0001_init.sql` — создаёт enum-ы, все семь таблиц, индексы и триггеры (один триггер автоматически создаёт профиль, когда пользователь регистрируется, другой пишет строку в `status_entries` каждый раз, когда меняется статус заявки)
- `0002_rls.sql` — включает Row Level Security и добавляет правила «только свои строки»
- `0003_storage.sql` — создаёт бакет хранилища `cvs` для загрузки CV

Миграция — это просто SQL-файл, который ты запускаешь один раз против своей базы данных. Два способа их запустить:

- **Вставить их:** открой SQL-редактор Supabase, вставь содержимое файла, нажми "Run". Делай их по порядку: 0001, затем 0002, затем 0003.
- **Запушить их через CLI:** `supabase db push` применяет все миграции за тебя.

Если получишь ошибку, скопируй сообщение об ошибке и попроси ИИ её исправить.

## Аутентификация: magic link

JobTracker не использует пароли. Он использует **magic link** (вход по ссылке из письма). Пользователь набирает свой email, Supabase присылает ему ссылку, он кликает по ней и заходит. Вот и весь вход.

- Никакого пароля, который надо выбирать, забывать или сливать.
- Клик попадает на `app/auth/callback/route.ts`, который завершает вход.
- `proxy.ts` и `lib/supabase/middleware.ts` держат сессию свежей при каждом запросе.

## Row Level Security (RLS)

Это самая важная часть. RLS — это правило на каждой таблице, которое говорит «пользователь может видеть и менять только свои строки».

В JobTracker RLS включён для **каждой таблицы** (`0002_rls.sql`). Так что даже несмотря на то, что anon key публичный:

- Ты видишь только свои заявки, чаты, заметки и контакты.
- Дочерние таблицы вроде `status_entries` и `chat_messages` наследуют владельца от родителя (заявки или чата, которым принадлежат).
- Бакет хранилища `cvs` приватный, и каждый пользователь может трогать только файлы внутри своей папки.

Без RLS любой с публичным ключом мог бы читать данные всех. С RLS база данных отказывает. Никогда не выключай его.

## Советы

- Запускай миграции по порядку (0001, 0002, 0003) при первой настройке базы данных.
- Используй дашборд Supabase, чтобы проверять свои данные. Это самый быстрый способ увидеть, работает ли всё.
- Если приложение запускается, но не показывает данных, проверь свои ключи, проверь, что ты залогинен, и проверь, что политики RLS были применены.
- Никогда не отключай Row Level Security, чтобы «заставить работать». Если ты не видишь строк, скорее всего, ты не залогинен, а не RLS виноват.
