## Запуск JobTracker

Это справочник по тому, как реально запустить проект на своём компьютере: какие инструменты ты используешь, что каждый из них делает и что делать, когда что-то идёт не так.

## Что нужно заранее

Сначала нужно установить несколько вещей:

- **Node.js** — версия LTS. Это даёт тебе `node` и `npm`.
- **npm** — идёт вместе с Node. Он ставит пакеты и запускает скрипты проекта.
- **git** — чтобы сохранять работу и пушить на GitHub.
- **Редактор кода** — VS Code хороший выбор по умолчанию.
- **Claude Code** (необязательно) — ИИ-ассистент. Удобен, но не обязателен для запуска приложения.

Проверь, что Node и npm на месте:

```bash
node -v
npm -v
```

## Настройка в первый раз

Сделай это один раз, по порядку:

1. **Установи пакеты:**

   ```bash
   npm install
   ```

2. **Настрой свои ключи.** Скопируй пример env-файла и заполни его:

   ```bash
   cp .env.example .env.local
   ```

   Затем открой `.env.local` и добавь свои `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` и `OPENAI_API_KEY`. Смотри руководства по Supabase и OpenAI, откуда их взять.

3. **Примени миграции базы данных.** Запусти SQL-файлы из `supabase/migrations/` (0001, потом 0002, потом 0003) в SQL-редакторе Supabase или выполни `supabase db push`. Смотри руководство по Supabase.

Теперь ты готов запускать.

## Команды

| Команда | Что она делает | Когда использовать | Что ты должен увидеть |
|---------|--------------|----------------|---------------------|
| `npm run dev` | Запускает dev-сервер Next.js | Ежедневная сборка. Эту команду ты используешь чаще всего. | Приложение по адресу **http://localhost:3009**, перезагружается по мере правок |
| `npm run build` | Делает production-сборку | Перед деплоем или чтобы проверить, что приложение компилируется без ошибок | «Compiled successfully» и список собранных маршрутов |
| `npm start` | Отдаёт production-сборку | Чтобы протестировать собранное приложение локально (сначала запусти `npm run build`) | Собранное приложение работает, без живой перезагрузки |
| `npm run lint` | Запускает ESLint | Перед коммитом, чтобы поймать проблемы в коде | «No ESLint warnings or errors» или список для исправления |
| `npm test` | Запускает юнит-тесты Vitest один раз | Перед коммитом, в CI, чтобы проверить, что логика всё ещё работает | Зелёная сводка pass/fail |
| `npm run test:watch` | Запускает Vitest и перезапускает при сохранении | Пока работаешь над логикой в `lib/` | Тесты перезапускаются каждый раз, когда ты сохраняешь |
| `npm run storybook` | Запускает мастерскую компонентов | Чтобы посмотреть один компонент изолированно | Storybook по адресу **http://localhost:6006** |
| `npm run build-storybook` | Собирает статичные файлы Storybook | Чтобы захостить или поделиться мастерской | Сгенерированная папка `storybook-static/` |

Про порт: обычный `npm run dev` использует порт Next по умолчанию. Этот проект настроен на запуск на **порту 3009** (смотри `.claude/launch.json`), поэтому приложение живёт по адресу **http://localhost:3009**. Чтобы задать его самому, запусти:

```bash
npm run dev -- -p 3009
```

## Какой инструмент что доказывает

Каждая команда отвечает на свой вопрос:

- **dev** — «выглядит и работает ли правильно?» Смотри вживую в браузере.
- **test** — «логика всё ещё работает?» Юнит-тесты в `lib/` всё ещё проходят.
- **lint и типы** — «код чистый?» Нет ошибок линтера, нет ошибок типов.
- **build** — «задеплоится ли?» Компилируется так же, как будет собирать Vercel.
- **storybook** — «выглядит ли этот один компонент правильно сам по себе?» Изолированно, во всех состояниях.

Безопасная привычка перед коммитом: запусти `npm run lint` и `npm test`, а `npm run build` — перед деплоем.

## Решение проблем

**Порт 3009 уже занят.** Другой процесс держит порт. Либо останови этот процесс, либо запусти dev-сервер на другом порту: `npm run dev -- -p 3010`. На Mac ты можешь узнать, что его использует, командой `lsof -i :3009`.

**Приложение запускается, но данные пустые.** Это почти всегда ключи или авторизация, а не баг. Проверь, что твои ключи Supabase в `.env.local` верные, что ты **вошёл** (magic link — вход по ссылке из письма, потом кликни по письму) и что миграции — включая политики RLS в `0002_rls.sql` — были применены. Помни: при включённом Row Level Security ты видишь только свои строки, поэтому пустой экран, когда ты не вошёл, — это ожидаемо.

**Ты изменил `.env.local`, но ничего не изменилось.** Переменные окружения читаются при запуске сервера. Останови dev-сервер и запусти `npm run dev` снова.

**Ошибки «Missing environment variable».** Не задан обязательный ключ. Убедись, что ты скопировал `.env.example` в `.env.local` и заполнил значения. Имена должны совпадать точно, включая префикс `NEXT_PUBLIC_` у двух ключей Supabase.

## Советы

- Держи dev-сервер запущенным в одной вкладке терминала, а вторую вкладку используй для `git`, `npm test` или Storybook.
- Если приложение странно себя ведёт после того, как ты подтянул новый код, запусти `npm install` снова — зависимости могли поменяться.
- Перезапускай dev-сервер каждый раз, когда трогаешь `.env.local`.
