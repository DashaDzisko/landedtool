

## Что такое стек

Стек — это набор инструментов, которыми ты строишь своё приложение. Представь, что перед стройкой ты выбираешь материалы. Дерево или металл? Шурупы или клей?

Для веб-приложения в стек входят фреймворк, инструмент для стилей, язык программирования и сервисы, которые хранят твои данные и добавляют умные функции.

У JobTracker (в коде он называется **"Landed"**) стек уже есть. Тебе не нужно ничего выбирать. Но полезно понимать, что за каждую часть отвечает и зачем она тут.

## Какой стек использует Landed

- **Next.js 16** (App Router) — фреймворк, на котором работает приложение
- **React 19** — библиотека, которая строит экраны
- **TypeScript** — язык программирования
- **Tailwind CSS v4** — инструмент для стилей и вёрстки
- **Supabase** — база данных и система входа
- **OpenAI** — ИИ, на котором работает чат-агент
- **Radix UI** — готовые блоки вроде диалогов и выпадающих списков
- **Phosphor icons** — набор иконок

Всё это можно увидеть в `package.json`. В этом файле перечислены все инструменты, которые устанавливает проект.

## Почему Next.js

Next.js — это фреймворк на базе React. Он берёт на себя страницы, маршрутизацию и серверную часть.

Почему он тебе подходит:
- ИИ знает его очень хорошо. Он видел миллионы примеров на Next.js.
- Он запускает и экраны, и небольшие API-маршруты в одном проекте. Landed использует это для своего чат-агента (`app/api/chats`).
- Он сразу работает с Vercel (где приложение выходит в интернет).

Landed использует более новый **App Router**, где каждая папка внутри `app/` — это маршрут. Не следуй старым туториалам, где используется папка `pages/` — это устаревший способ.

## Почему React

React — самый популярный инструмент для построения веб-экранов. Ты описываешь, как должен выглядеть экран, а React сам обновляет его, когда данные меняются.

Здесь ты не пишешь React с нуля. Приложение собрано из небольших компонентов в `components/` (атомы, молекулы, организмы). ИИ очень уверенно их редактирует.

## Почему TypeScript

TypeScript — это JavaScript с дополнительной защитой. Он подсказывает тебе, что что-то не так, ещё до того, как приложение сломается.

Тебе не нужно учить его глубоко. ИИ пишет его за тебя. Но он помогает ИИ делать меньше ошибок, потому что правила строже. Landed даже хранит формы своих объектов в `types/`, чтобы всё приложение одинаково понимало, что такое «Application».

## Почему Tailwind CSS v4

Tailwind позволяет задавать стили прямо в коде. Ты добавляешь имена классов вроде `bg-canvas` или `text-primary` вместо того, чтобы писать отдельные CSS-файлы.

Версия 4 немного отличается от старых. **Файла `tailwind.config.ts` больше нет.** Вместо этого дизайн-токены (цвета, шрифты, размеры) живут как CSS-переменные в одном файле — `app/globals.css`, внутри блока `@theme inline`. Ты меняешь токены там, и классы обновляются везде.

Почему это тебе подходит:
- Если ты знаешь дизайн, Tailwind ложится на то, что ты уже знаешь: отступы, интервалы, цвета.
- ИИ очень хорошо пишет Tailwind и почти никогда не ошибается с ним.

## Почему Supabase

Supabase — это база данных плюс система входа. Она хранит каждое приложение, чат и профиль. Она же отвечает за вход по **magic link** (вход по ссылке из письма) — пользователь получает письмо, кликает по ссылке и заходит. Никаких паролей запоминать не надо.

Supabase ещё и защищает данные с помощью Row Level Security, так что каждый пользователь видит только свои строки. Об этом подробнее в уроках про API и безопасность.

## Почему OpenAI

OpenAI — мозг чат-агента. Когда ты пишешь Landed, твоё сообщение и данные твоих заявок отправляются в OpenAI, и он отвечает. Модель по умолчанию — `gpt-4o-mini`. Всё это работает на сервере, никогда в браузере, так что твой ключ остаётся приватным.

## Почему Radix и Phosphor

- **Radix UI** даёт тебе корректные, доступные блоки — диалоги, выпадающие списки, вкладки, селекты. Landed оборачивает их в `components/ui/` и оформляет своими токенами.
- **Phosphor** — набор иконок, который используется по всему приложению.

Тебе не нужно строить всё это с нуля. В этом и смысл — хорошие настройки по умолчанию, чтобы ты тратил время на свой продукт.

## А как же другие варианты

Ты можешь услышать о других инструментах:

- **Vue, Svelte, Angular** — другие фреймворки. Они работают, но ИИ лучше всего знает React и Next.js.
- **Обычный CSS, SCSS** — другие варианты для стилей. Они работают, но с ИИ Tailwind быстрее.
- **Firebase, чистый SQL** — другие варианты для базы данных. Supabase даёт тебе базу, вход и правила безопасности в одном месте.

Landed уже сделал этот выбор. Твоя задача — строить поверх него, а не менять его.

## Советы

- Не воюй со стеком. Разберись в нескольких частях выше — и ты сможешь понять всё приложение.
- Когда ИИ предлагает инструмент, которого нет в `package.json`, спроси зачем, прежде чем добавлять. Меньше инструментов — меньше того, что может сломаться.
- Если в туториале упоминается `tailwind.config.ts`, помни: в v4 токены хранятся в `app/globals.css`.
