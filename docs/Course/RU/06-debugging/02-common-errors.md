
## Module not found

```
Module not found: Can't resolve '@/components/organisms/chat/chat-panel'
```

**Что это значит:** Файла по этому пути не существует. Либо файл никогда не создавался, либо его переименовали, либо путь неправильный.

**Как исправить:** Проверь, что файл существует. Проверь опечатки в пути импорта. Спроси ИИ: "Я получаю Module not found для @/components/organisms/chat/chat-panel. Можешь проверить, существует ли файл, и исправить импорт?"

## Cannot read properties of undefined

```
TypeError: Cannot read properties of undefined (reading 'map')
```

**Что это значит:** Твой код пытается использовать что-то, чего ещё нет. В Landed это часто случается, когда заявки или сообщения чата ещё не загрузились из Supabase.

**Как исправить:** Спроси ИИ: "Я получаю 'Cannot read properties of undefined reading map'. Заявки, возможно, ещё не загрузились. Добавь проверку загрузки перед использованием данных."

## Ошибка гидратации (Hydration error)

```
Hydration failed because the initial UI does not match what was rendered on the server
```

**Что это значит:** Страница выглядит по-разному на сервере и в браузере. Это часто случается, когда ты используешь вещи, которые есть только в браузере (например `window` или `localStorage`), во время первого рендера.

**Как исправить:** Спроси ИИ: "Я получаю ошибку гидратации. Можешь проверить, использует ли какой-то код window или браузерные API во время серверного рендеринга, и обернуть его в useEffect?"

## Ошибка типа (Type error)

```
Type 'string' is not assignable to type 'ApplicationStatus'
```

**Что это значит:** TypeScript ожидал один тип данных, а получил другой. В Landed статус должен быть одним из `saved | applied | screening | interview | offer | rejected | withdrawn`. Передача любого другого текста даёт эту ошибку.

**Как исправить:** Скопируй ошибку и попроси ИИ исправить тип. Обычно это быстрые исправления.

## 404 page not found

**Что это значит:** Страницы не существует. Либо маршрут неправильный, либо файл лежит не в той папке.

**Как исправить:** В Next.js страницы лежат в папке `app`. Страница по адресу `/settings` требует файл `app/(app)/settings/page.tsx`. Проверь, что файл лежит в правильном месте.

## Build failed

```
Build error occurred
```

**Что это значит:** Твоё приложение не может собраться. Это случается, когда ты запускаешь `npm run build` или делаешь деплой на Vercel. Что-то в коде сломано.

**Как исправить:** Прочитай ошибку под строкой "build failed". Обычно она указывает на проблему. Скопируй полную ошибку и попроси ИИ исправить её.

## CORS error

```
Access to fetch has been blocked by CORS policy
```

**Что это значит:** Твоё приложение пытается вызвать API из браузера, который этого не разрешает. Это функция безопасности.

**Как исправить:** Спроси ИИ: "Я получаю ошибку CORS при вызове [название API]. Как это исправить? Стоит ли вызывать его из серверного API-маршрута вместо этого?"

В Landed чат-агент уже работает так. Браузер вызывает `app/api/chats/[chatId]/route.ts`, и этот маршрут общается с OpenAI на сервере. Ключ OpenAI никогда не попадает в браузер.

## Environment variable is undefined

```
Error: Missing environment variable NEXT_PUBLIC_SUPABASE_URL
```

**Что это значит:** Твоё приложение не может найти ключ, который ему нужен. Либо файл `.env.local` отсутствует, либо имя переменной неправильное.

**Как исправить:** Проверь файл `.env.local`. В нём должны быть эти три, скопированные из `.env.example`:

```bash
NEXT_PUBLIC_SUPABASE_URL=...
NEXT_PUBLIC_SUPABASE_ANON_KEY=...
OPENAI_API_KEY=...
```

Убедись, что каждое имя совпадает точно. Потом перезапусти dev-сервер (останови его и снова запусти `npm run dev`). Next.js читает `.env.local` только при старте, поэтому изменения требуют перезапуска.

## Приложение загружается, но список заявок пустой

У этой проблемы нет красной ошибки. Доска Канбан просто ничего не показывает. Обычно одна из трёх причин:

- **Ты не вошёл в систему.** Landed использует вход по magic link (вход по ссылке из письма). Если нет сессии, нет пользователя, значит нет данных. Сначала войди.
- **RLS фильтрует строки, и это правильно.** Supabase Row Level Security даёт тебе видеть только твои собственные заявки. Пустая доска для совсем нового аккаунта — это ожидаемо. Это не баг.
- **Твои ключи Supabase неправильные.** Если `NEXT_PUBLIC_SUPABASE_URL` или `NEXT_PUBLIC_SUPABASE_ANON_KEY` указывают на неправильный проект, ты подключаешься к базе данных без твоих данных. Ещё раз проверь `.env.local`.

Спроси ИИ: "Приложение загружается, но моя доска заявок пустая. Помоги проверить, вошёл ли я в систему, фильтрует ли RLS мои строки и правильные ли мои ключи Supabase в .env.local."

## Too many re-renders

```
Error: Too many re-renders. React limits the number of renders to prevent an infinite loop.
```

**Что это значит:** Что-то в твоём коде обновляется без остановки. Обычно это обновление состояния внутри рендера или пропущенная зависимость в `useEffect`.

**Как исправить:** Скопируй ошибку и файл компонента. Спроси ИИ: "Этот компонент вызывает too many re-renders. Можешь найти цикл и исправить его?"

## Советы

- Большинство ошибок, которые ты увидишь, есть в этом списке. Через пару недель ты будешь узнавать их, не читая всё сообщение.
- Всегда копируй полную ошибку для ИИ. Не пытайся объяснить её своими словами.
- Пустая доска обычно про вход или RLS, а не про падение. Сначала проверь, под кем ты вошёл.
- Если одна и та же ошибка возвращается снова, добавь правило в свой claude.md, чтобы её предотвратить.
