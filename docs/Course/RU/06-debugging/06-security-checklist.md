
## Чек-лист, которым реально можно пользоваться

Тебе не нужно быть экспертом по безопасности, чтобы держать Landed в безопасности. Тебе нужен короткий список, по которому можно пройти руками, прежде чем показать приложение реальным людям. Это важно, потому что Landed хранит реальные, приватные данные: заявки людей на работу, компании, с которыми они общаются, их заметки, их контакты. Одна пропущенная проверка, например Row Level Security, оставленный выключенным на одной таблице, может слить данные всех пользователей разом. Пройди по этому списку перед первым деплоем и снова перед каждым деплоем после этого.

Ставь галочку в каждом пункте только тогда, когда действительно посмотрел и подтвердил это. "ИИ, наверное, это сделал" — это не проверка.

## Секреты

- [ ] `.env.local` указан в `.gitignore` и не закоммичен в Git.
- [ ] Никакие API-ключи, токены или пароли не зашиты в код где-либо. Они все живут в `.env.local`.
- [ ] У `OPENAI_API_KEY` НЕТ префикса `NEXT_PUBLIC_`, поэтому он остаётся только на сервере.
- [ ] `OPENAI_API_KEY` используется только внутри маршрутов `app/api/chats`, никогда в клиентском компоненте.
- [ ] Если какой-то ключ когда-либо был вставлен в чат, скриншот или публичный репозиторий, ты сменил его (сгенерировал новый) и обновил `.env.local`.

## База данных (Supabase)

- [ ] Row Level Security включён на КАЖДОЙ таблице: `profiles`, `applications`, `status_entries`, `notes`, `contacts`, `chats`, `chat_messages`.
- [ ] Каждая политика ограничивает строки текущим пользователем через `auth.uid()` (только свои строки).
- [ ] Дочерние таблицы получают владельца от своей родительской: `status_entries`, `notes` и `contacts` проверяют свою заявку; `chat_messages` проверяет свой чат.
- [ ] Ты добавил тот же шаблон RLS к любой НОВОЙ таблице, которую создал.
- [ ] Ключ service-role, если ты вообще его используешь, только на сервере и никогда не отправляется в браузер.

## Аутентификация и маршруты

- [ ] Защищённые страницы (оболочка приложения, настройки, детали заявки) перенаправляют на вход, когда ты вышел из системы.
- [ ] Каждый маршрут `/api`, который трогает данные пользователя, сначала проверяет сессию, прежде чем что-либо читать или писать.
- [ ] Вход по magic link работает: войти, вернуться в приложение и видеть только свои собственные данные.

## Ввод

- [ ] Каждая форма валидирует свой ввод (обязательные поля, разумная длина и тип): форма magic-link, форма заявки, форма профиля, поле ввода чата.
- [ ] Ввод пользователя очищается перед тем, как его сохранить или показать, чтобы никто не смог внедрить HTML или JavaScript.
- [ ] Ты никогда не доверяешь данным формы как есть. Сервер проверяет их снова, даже если браузер уже это сделал.

## Правила специально для вайбкодинга

- [ ] Ты никогда не вставляешь реальные секреты или реальные данные пользователей в промпт для ИИ.
- [ ] Ты всегда читаешь SQL и миграции, сгенерированные ИИ, прежде чем их запускать. Если миграция трогает RLS или удаляет политику, ты сначала понимаешь, что она делает.
- [ ] Ты запускаешь `npm audit` и просматриваешь любой новый пакет перед его добавлением. Неизвестные пакеты — это реальный риск.
- [ ] Ты перезапускаешь эти проверки безопасности перед каждым деплоем, а не только перед первым.

## Если нашёл проблему

Не паникуй и не делай деплой. Сначала исправь самые опасные пункты: открытый `OPENAI_API_KEY`, отсутствующую проверку сессии на API-маршруте или RLS, оставленный выключенным на таблице. Если ключ утёк, смени его сразу же. Когда не уверен, как что-то исправить, вставь находку в Claude Code с путём к файлу и попроси самое маленькое безопасное изменение. Потом пройди по всему чек-листу снова с начала. Для более глубокого, направляемого обзора используй готовый промпт в `docs/security-check-prompt.md`.
