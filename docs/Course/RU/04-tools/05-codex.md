
## Что это

Codex — это кодинг-агент от OpenAI. Он подключается к твоему репозиторию на GitHub и работает над задачами в фоне. Ты даёшь ему задачу, он создаёт ветку, пишет код и открывает pull request, чтобы ты его проверила.

Думай об этом как о найме джуна. Ты даёшь ему тикет, он делает работу, а ты проверяешь её до того, как всё уйдёт в прод.

## Как это работает

1. Ты подключаешь Codex к своему репозиторию на GitHub.
2. Ты описываешь задачу. «Добавь фильтр по статусу withdrawn на Канбан-доску».
3. Codex работает над ней в фоне. Ждать не нужно.
4. Когда он закончит, ты получаешь pull request на GitHub.
5. Ты проверяешь изменения. Если всё хорошо, ты их вливаешь.

Можно давать ему несколько задач одновременно. Он работает над ними параллельно.

## Для чего он хорош

- Задачи, которые можно чётко описать. «Добавь страницу 404». «Почини битую ссылку в футере».
- Фоновая работа. Ты описываешь задачу и продолжаешь заниматься другими делами.
- Маленькие и средние функции. Добавить страницу, починить баг, обновить стили.
- Работа с существующим проектом на GitHub.
- **Проверки безопасности.** Ты можешь попросить Codex проверить твой код на проблемы с безопасностью. «Проверь мой проект на уязвимости безопасности». Он смотрит на код и находит такие вещи, как открытый API-ключ OpenAI, отсутствие валидации ввода или небезопасные запросы к базе данных. Это очень полезно, потому что как дизайнер ты можешь не знать, что делает код небезопасным.

## Для чего он НЕ хорош

- Задачи, где нужен диалог туда-обратно. Codex работает сам по себе, ты не можешь общаться с ним, пока он работает.
- Очень сложные функции, где по ходу дела нужно принимать много решений.
- Проекты, которых нет на GitHub.

## Как начать

1. Зайди на chatgpt.com/codex (нужен план ChatGPT Plus или Team).
2. Подключи свой аккаунт GitHub.
3. Выбери репозиторий.
4. Напиши задачу и дай ему поработать.

## Как он сравнивается с другими инструментами

| | Codex | Claude Code | Cursor |
|---|---|---|---|
| Где работает | В облаке | В твоём терминале | В твоём редакторе |
| Как общаешься | Даёшь задачу, ждёшь | Диалог туда-сюда | Чат и правки прямо в коде |
| Нужен GitHub | Да | Нет | Нет |
| Для чего хорош | Фоновые задачи | Сложные фичи | Визуальное редактирование |
| Как проверяешь | Pull request | Подтверждение в терминале | Принятие диффов в редакторе |

## Советы

- Пиши чёткие задачи с конкретными деталями. «Добавь форму обратной связи с полями имя, email и сообщение на страницу деталей отклика» лучше, чем «добавь форму».
- Внимательно проверяй pull request. Убедись, что Codex не изменил файлы, о которых ты не просила.
- Начни с маленьких задач, чтобы понять, как он работает. Исправление бага или простая страница.
- Используй Codex для задач, которые ты не хочешь делать сама. А Claude Code или Cursor — для задач, где ты хочешь участвовать шаг за шагом.
